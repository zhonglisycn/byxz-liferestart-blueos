## 布局修复（2026-10-05 第三版）：页面被挤出屏幕

### 一、现象与根因

用户截图实证：**「抽词条」页在 432×514 上内容超出屏幕**，底部操作行（换一批 / 下一步）
被挤到屏幕外，看不到也点不到；卡片区和"说明块"把高度吃光。

按页面逐块量一遍（`屏幕 514 − 上下内边距 22 = 可用 492`）：

| 修复前「抽词条」的区块 | 高度 |
| --- | --- |
| 顶栏 | 50 |
| 状态行（已选 x/3） | 34 + 2 间距 |
| 卡片区 5 行 ×（50 卡高 + 5 行距） | 275 + 2 间距 |
| 说明块（`min-height: 60` + 上下 padding 16） | 76 + 2 间距 |
| 底部操作行 | 64 |
| **合计** | **505 > 492，底部按钮被挤出去 13px** |

根因不是某一页写错了一个高度，而是**每页各自手写高度、没人算总账**。同类排查（旧结构）：

| 页面 | 旧结构问题 |
| --- | --- |
| Talents | 505 > 492，**硬超屏**（用户截图的那一页） |
| Alloc | 约 478~490，只剩 2~14px 余量；天赋摘要一旦换行（多一个 26px 行）就顶出去 |
| End | 结局说明是变高文本（`ending.desc` 可长可短），长文案会把滚动区压到 12px 甚至超屏 |
| Archive | 不超屏，但三个存档槽的「读取 / 删除」按钮**在 scroll 里**，不滚动就点不到 |
| Home / Life / Codex / About | 装得下，但也把"高度"散在各页手写，改一处就容易互相挤压 |

### 二、修法一：全工程共用的高度总账 `common/core/layout.js`

新增 **纯函数** `layout(spec)`（不 import 任何平台接口，Node 可直接单测），
把"屏幕 − 内边距 = 可用高度"这条账集中算：

- 输入：屏幕（默认 432×514）、页面内边距（默认 10/12）、区块表 `[{ k, h, gap, flex, min }]`；
- 输出：`avail`（可用高度）、每个区块的应得高度 `blocks`、`fixed/gaps/used`、
  **滚动区高度 `zone`**、`fits/overflow`（固定块是否超出）、带 `rows` 时还算
  `visible`（一屏完整看到几行）/`pages`（要滚几页）/`enough`；
- 超屏时 `zone` 归 0 并置 `overflow`（不产生负高度）；
- `layoutOf('Talents')` 按页面名取本页总账，**8 个页面都 import 它**，
  把算出来的高度绑到样式上（`style="height: {{zoneH}}px"`、卡片 `{{cardH}}px`…），
  不再手写互相挤压的 px；`core.test.mjs` 逐页断言"占用 + 滚动区 = 492"并与 CSS 数字对账。

### 三、修法二：「抽词条」页重排为固定三段

```
顶栏 50
信息行 30        已选 x / 3            换一批 N 次 · 共 M 条
已选摘要 28      已选：XX · XX · XX（一行，超长截断；不再在底部占一块）
──────────────────────────────────────────────
卡片区 306       scroll-y（唯一可滚动区）；10 张卡两列 × 五行
                 卡片高 62px + 行距 6 → 一屏完整看全 4 行，滚一屏看完剩下 1 行
                 点词条的说明（52px 两行）放在滚动区顶部，不再占底部高度
──────────────────────────────────────────────
底部操作行 64    换一批 / 下一步（在 scroll 之外，任何情况下可见可点）
```

- 「换一批」的计数挪进顶部信息行；已选摘要固定一行（`SUMMARY_MAX = 21` 字，
  21×19px = 399 ≤ 404，放得下）；点卡片的长说明截到 40 字，进滚动区；
- 「下一步」按钮文案由「下一步 · 分配属性」压成「下一步」（原来 10 个字在 254px 胶囊里会溢出）；
- 底部按钮与滚动区是**兄弟节点**，结构断言直接查模板：
  滚动区里不许出现 `class="...btn"`，`class="btn-row"` 必须在 `</scroll>` 之后。

## 本次修复（2026-10-05，模拟器实测后）

### 1（严重）进「分配属性」页应用退出

**现象**（模拟器日志，2026-10-05 09:12）：从抽词条页点「下一步 · 分配属性」，
`RouterUtils replace` 在同一秒连打数次、`page is not nullptr`，随后
`JsThread skip change page visible: page: pages/Alloc, visible: 0`、
`RenderOpManager handleRenderOpsInMainThread no page id: 6`，应用退出。

**根因**：模块级单例在蓝河上**不是跨页单例**。
打包器按页面打包，公共模块会被**内联进每个页面的字节码**（`build/watch-square/pages/*/index.js`
里各有一份完整的 `const app = {...}` / `storage` / `engine` 代码），页面各自执行一份：

- `pages/Talents/index.ux` 的 `next()` 调 `app.setRun(run)` 写的是 **Talents 那一份**内存；
- `pages/Alloc/index.ux` 旧代码第 57 行 `if (!run) { router.replace({ uri: 'pages/Home' }); return }`
  读的是 **Alloc 那一份**，`app.run` 永远是 `null`；
- 于是页面一创建就立刻 `replace` 回首页。这次 `replace` 落在"正在创建的页面上"，
  框架侧页面一直不可见（`visible: 0`），排队的渲染指令找不到页面（`no page id`），应用退出。

也就是说：这不是用户手快点了两下，而是**每次进这一页都必然发生**；同一个坑也影响
首页"继续人生"、图鉴进度、结算页（它们读到的都是各自页面里的空状态）。

**修法**（三层，缺一不可）：

1. **状态挂到平台的应用级对象上**：新增 `src/common/core/shared.js`，
   `stateOf(this)` 依次尝试 `this.$app.$def`（quick-app 的应用级对象）→ `globalThis`
   → 模块本地兜底，命中的容器会**镜像到所有可用宿主**；`app.js` 改成门面
   （`app.attach(this)` 在 `onInit`/`onShow` 接入共享容器，`run`/`codexSeen` 共享引用，
   标量由 `setXxx`/`markCodex` 写回），`app.ux` 的 `onCreate` 也调 `attach(this)`。
   最坏情况（两条宿主都没有）会退化成页面本地状态，并往日志里留一行 `console.warn` 便于真机定位。
2. **跳转幂等**：新增 `src/common/core/nav.js` + `nav-gate.js`，所有页面的
   `router.replace/push/back` 统一走 `go()/back()`；同一目标 700ms 内的重复请求、
   距上次跳转不足 150ms 的任何跳转一律丢弃（页面切换本身要几百毫秒，被丢的都是重复点击）。
3. **不再从生命周期里跳页**：`Alloc`/`Life`/`End` 去掉"没数据就 replace 回首页"，
   改成渲染占位（「没有进行中的人生 / 回首页」）——即使状态异常，页面也不再自己炸掉，
   而是给用户一个明确出口。

### 2 图鉴页进不去 / 极卡

**现象**：进 Codex 页要很久甚至进不去（该页 bundle 约 519KB，进页要把 2256 条内容池
装配一遍、再对当前分类逐条拼显示文案：默认词条 649 条，事件分类 1065 条）。

**修法**：

1. **文案预生成**：新增 `src/common/core/codex-build.js`，`tools/gen-stats.mjs` 在生成
   `stats.js` 的同时生成 `src/common/core/codex-index.js`（349KB 源码，一行一条，字段用
   `\u0001` 分隔：id ␁ 显示名 ␁ 说明 ␁ 原文 ␁ 颜色类）。图鉴页**不再 import 内容池**
   （编译产物里已无 `ALL_TALENTS` / `effText` / `buildContent`），也不在进页时排序/去重/拼字符串；
   `core.test.mjs` 会重新生成一遍与文件逐行比对，防止内容改了忘跑生成器。
2. **只做当前页**：`buildPool()` 只在"已得/未得"筛选时建一个行号数组（判锁只看 id）；
   `showPage()` 只把当前页这 14 行拆成显示对象。切分类/翻页都不再遍历全量。
3. **每页条数 20 → 14**：一屏最多 14×3=42 个文本节点（原来 20×3=60），切页更快。
4. 顺带修掉一处旧显示 bug：结局里有 22 条 `rank: 5` 的内容，原来会显示成「（undefined）」
   （`RARITY_NAME[5]` 越界）——`engine.js` 的 `RARITY_NAME` 补上第 5 档「传说」，
   图鉴补 `.r5` 配色。

**开销对比**（同一台机器、同一个打包命令，取自 `build/watch-square/pages/*/index.js` 与 `dist/`）：

| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| Alloc 页字节码 | 506,751 B（背着 2256 条内容池） | **11,919 B**（-97.7%，不 import 内容池） |
| Codex 页字节码 | 519,120 B | **310,196 B**（-40.2%） |

| release 包 | 1,159,458 B | **941,786 B**（-18.8%） |

第 1 项的效果：进 Alloc 不再有"页面装载几百毫秒 → 看似没反应"的窗口，
配合跳转闸门与占位兜底，重复 `replace` 与应用退出两条路都被堵上。

### 三、存档槽设计（2 手动 + 1 自动，键名前缀不变）

| 槽位 | storage 键 | 语义 |
| --- | --- | --- |
| 自动档 | `lrgt_run`（**沿用原键**） | 默认槽位；老存档升级后直接落在自动档，不会因为分槽丢档 |
| 存档一 | `lrgt_slot1` | 手动槽：只有在首页选中它并真正开始/继续一局时才被写入 |
| 存档二 | `lrgt_slot2` | 同上 |
| 记忆 | `lrgt_slot` | 上次选中的槽位（'auto' / 's1' / 's2'，坏的当 auto） |
| 最近结局 | `lrgt_last` | 结算页写的小记录（结局名/评级/评分/享年/体系），首页卡片只读这几十字节 |

- 纯逻辑在 `save.js`：`SLOT_IDS / slotKey / isSlot / emptySlots / parseSlots / slotInfo /
  serializeLast / parseLast`，全部可单测；存储读写仍走 `util.js`（全 try/catch）。
- 跨页读取走 `shared.js` 的应用级容器：`s.slots`（三个 run）+ `s.slot`（当前槽），
  页面照旧 `app.attach(this)` + `app.sync()`（`app.run` 恒等于 `slots[slot]`）。
- 坏档/死人档不进槽（`isResumable` 过滤）；死了就删该槽的键，首页不会出现"可以继续的死人"。
- 手动槽的取舍：它不会自动被"换一批"覆盖（换一批只改内存里的未开局 run，不落盘），
  适合把长局单独留着。

## 已知限制

1. **没有在真机上装过**（本机无表）。模拟器预览、侧载 (OrbitV)、存储/震动签名都要真机确认：
   - **本次修复的核心假设**：`shared.js` 取共享容器的顺序是
     `this.$app.$def` → `globalThis` → 本地兜底。模拟器的框架两条都有；
     真机上如果两条都取不到，会退化成"页面各自一份状态"，日志里会打一行
     `[liferestart] 没有可用的应用级共享宿主…`。装机后先看这一行在不在；
     再看「抽词条 → 下一页」：分配属性页顶上应显示「天赋：xxx」，
     如果显示「没有进行中的人生」占位，说明这台机器的共享宿主不是这两条路，
     需要按真机行为改 `shared.js`（只需改 `resolveHolder` 一个函数）。
   - `@blueos.storage.storage` 的 `set/get/delete`：全部 try/catch，最坏是"不存档"；
     装机后重点看"推进一年 → 退出 → 重进 → 继续人生"是否还在。
   - `@blueos.hardware.vibrator.vibrator` 的 `vibrate({mode:'short'})`：不支持就静默。
   - 自制排版在方屏上的实际观感（一行两格的宽度、图鉴 6 个标签、按钮高度）；
     图鉴进页速度与翻页手感（14 条一页，预生成索引）。
2. **页面字节码里各带一份内容池**（release 包里 `Life` 375KB / `Talents` 371KB / `End` 367KB）：
   蓝河打包器按页面打包，公共模块会内联。`Home`（8.2KB）/`Archive`（14KB）/`Alloc`（9.5KB）/
   `About`（7.8KB）已经不 import 内容池（首页只读 `stats.js` + `views.js`；档案页只读
   `stats.js` + 共享容器 + 存档记录 + engine 的阶梯常量，`Alloc` 只读 `run.talentNames`，
   Codex 只读预生成索引 332KB），其余页面还需要内容池本身
   （抽词条要抽卡池、Life 要事件池、End 要结局池）。
   release 包 1.02MB（上限 1.3MB）；真机上若出现页面切换卡顿，下一步是把内容按分类拆包。
3. 记录型内容（词条/事件/结局/成就）以原作 2.3.3 为基础：前两批（T001~T598 等）
   原样搬运，第三批 +78 条为本轮新增（schema 与文案风格对齐，见「本次丰富」）。
   图鉴的"未解锁"显示 `？？？` 与手环版一致。唯一一处显示修正：结局里 22 条
   `rank: 5` 的内容，原来会拼出"（undefined）"，现按第 5 档「传说」显示。
   另一个要注意的口径：新结局被放在 endings 池最前（同 rank 先匹配者胜），
   这是为了让具体结局不被通用结局遮蔽，rank 优先级本身没动。
4. `designWidth` 432 只在 432 宽方屏（GT2 等）上是 1:1；圆表 `watch` 也在 `deviceTypeList` 里，
   但排版是按方屏算的，圆表上四角可能被切——真机是圆表的话把 `deviceTypeList` 改成
   `["watch-square"]`，或后续加媒体查询分流。
5. `flex-wrap`、`overflow`、`line-height` 一律没用；`position: absolute` 也没用（本作不需要浮层，
   弹层用"整页替换 + if"实现，避开模拟器/真机差异）。
